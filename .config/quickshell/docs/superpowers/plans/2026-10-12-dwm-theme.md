# dwm Theme Implementation Plan

Superseded by `docs/superpowers/specs/2026-10-13-elena-only-controls-design.md`.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `dwm` UI style: a flat dwm-style one-line bar and a dmenu-style strip launcher drawn over it, in wallpaper (Matugen) colors.

**Architecture:** `Settings.themeStyle === "dwm"` gates everything through a new `Config.dwmTheme`. The bar reuses the Ghost one-liner code path (`bar/Bar.qml`). The launcher (`bar/LauncherPopup.qml`) reshapes itself into a top/bottom-anchored full-width strip and reparents its existing `searchInputControl` into a new horizontal row bound to the same `filteredModel`/`selectedIndex`. No new windows, no duplicated search logic.

**Tech Stack:** QML (Quickshell, QtQuick 6), one pure JS helper (`config/BarForm.js`), node `assert` tests, bash IPC gates, `qmllint`.

## Global Constraints

- Style id is the string `"dwm"`; accessor is `Config.dwmTheme`.
- Palette is wallpaper-driven (Matugen roles). No fixed suckless palette.
- Square corners, no shadow, no blur, font family `monospace`.
- Selected scheme (dwm SchemeSel): `Colors.primary` background, `Colors.fgPrimary` text.
- Bar surface: `Colors.surfaceContainerLowest`; normal text `Colors.fgSurface`.
- Never write the user's real `~/.config/quickshell/settings.json` while testing. Switch style in memory with `qs ipc call shell style dwm ""`.
- QML edits go live on save in the running shell. Run `bash scripts/m3-qmllint-gate.sh` after every QML edit so a parse error never reaches the live bar.
- VCS is `yadm` (there is no `.git` here). Commit messages end with the attribution lines from the session.
- Vertical bars keep their current layout with dwm colors; the dmenu strip applies only when the bar is horizontal (top or bottom).
- Not an LLM feature: no eval suite applies. Gate tests plus screenshot checks are the proof.

## Deviations from the spec (decided while reading the code)

| Spec said | Plan does | Why |
|---|---|---|
| Status text without icons | Keep icons, flatten pills, use text color | A bare `40%` with no icon is unreadable; indicators already pair icon + value |
| Layout symbol `[]=` | Shown only when the existing `layout` widget is available (Mango) | `layoutAvailable` is `Config.isMango && ...`; no layout data under Niri |
| Keys: Left/Right, Tab | Left/Right/Up/Down move, Enter launches, Esc dismisses | `TextFieldControl` exposes these signals; Tab has no hook, arrows always move selection (no in-field cursor movement via arrows) |
| dwm forces top bar | Honors the saved edge, strip only when horizontal | Same rule Ghost uses (`shell.qml:83` comment); no new position logic |
